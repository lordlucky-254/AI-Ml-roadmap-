# Contributing

Thanks for helping make this guide clearer and more useful. Contributions can include fixing an error, improving an explanation, adding a worked exercise, suggesting an accessible alternative, or replacing a broken learning link.

## Principles

- Prefer clear explanations, small reproducible examples, and practical checkpoints over long lists of jargon.
- Separate durable concepts from tool-specific instructions that may change.
- State prerequisites, expected effort, and what a learner should be able to do afterward.
- Favor official documentation, open educational material, and primary sources. Say when a resource requires payment, registration, or special hardware.
- Check links and attribution. Do not paste copyrighted books, course materials, datasets, or solutions without permission.
- Treat privacy, safety, fairness, and data licensing as part of the technical work.
- Keep the guide welcoming to learners with different backgrounds, devices, bandwidth, and accessibility needs.

## Suggested workflow

1. Fork the repository and make a focused change on a branch.
2. Preview the Markdown and test any code examples that you change.
3. Check relative links and ensure no data, credentials, or private information are included.
4. Open a pull request describing the learner problem your change solves and how you checked it.

Small corrections can be raised as an issue first. Please do not promise that a model, resource, or learning timeline guarantees a job or a particular result.
